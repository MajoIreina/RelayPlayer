# 播放后端 · v0.1.9

## GitHub 下载版的 PS5 网络串流

默认保留原来的 Relay 播放器和连接面板。局域网发现、Sony 浏览器授权、配对、唤醒、选定主机与删除记录由 Rust 连接模块处理，使用内置的 chiaki-rust 协议子集。普通串流使用固定 chiaki-ng v1.10.1；启用 NR 后使用固定社区运行时，见 [NR 声明](../notices/CHIAKI-NR.md)。

准备组件后，宿主向已绑定的独立配置同步选定主机，使用 `--dualsense --exit-app-on-stream-exit -- stream <内部唯一别名> <主机地址>` 启动。密钥不出现在命令行。生产代码拒绝空参数启动，不能回退到后端管理首页。宿主只按自己启动的精确 PID 嵌入 Qt 串流窗口，并对该 PID 调整音量。会话退出直接结束进程。

从 0.1.11 起，公开播放组件也归属每次启动单独创建的 Windows Job，设置关闭最后一个 Job 句柄时清理进程。关闭宿主时先向本次启动的播放进程发送 WM_CLOSE（包括嵌在宿主下的窗口），关闭输入通道，最多等待 750 ms，再清理仍存活的进程及其辅助进程；最后才释放嵌入表面，避免还原出第二个播放窗口。自然退出时也先清理 Job，再等待输出读取线程，防止辅助进程持有管道而阻塞退出。宿主被强制结束后由 Windows 清理所管理的播放组件，清理不按进程名查找，不影响其他播放器实例。退出不会删除配对或设置。

0.1.12 的 Relay 渲染适配器改用 stdin `{"type":"stop"}` 请求直接断开，不经过「是否休眠」确认；旧接口组件仍可使用 WM_CLOSE。宿主以同一 750 ms 截止时间处理正常退出与超时清理。原生 stats 消息内的 gpu 对象、画面来源、Kbps 码率和输出呈现帧率同步到状态面板；连续 4 秒没有状态更新即隐藏旧指标。能力未知、已证实支持和本次运行失败分开表达，用户设置值不充当实测结果。

支持分辨率、帧率、目标码率（最高 200,000 Kbps）、编码、NR；设置经校验与写入读回，在下一次连接使用，播放中显示待重连。尚未接入的选项在原面板禁用。后端报告收到实际视频包后才进入播放状态；不以进程启动作为帧、码率或 NR 生效的证明。

首次从固定 HTTPS 地址取得完整运行时并验证 SHA-256；离线 `--backend-archive` 不跳过校验。网络路径不实现以下 JSON IPC 协议，PSN 异地穿透与采集卡尚未接入。

## 可选 IPC 接口

`RelayPlayer.exe --ipc-backend` 才使用以下接口。用于开发或使用支持嵌入或采集的独立后端；默认网络后端不实现此协议。`--import-legacy` 也会选择此模式，并仅在允许时导入旧数据。

## 启动与退出

在 `RelayPlayer.exe` 同目录下放置 `backend/relay-backend.exe`。宿主通过绝对路径启动它，工作目录为播放器根目录。环境变量 `RELAY_ROOT`、`RELAY_DATA`、`RELAY_HOST_PID` 分别给出此实例的根目录、数据目录和宿主 PID。宿主不传命令行参数；`RELAY_PLAYER_ROOT` 只改变数据存放位置，不能指定可执行文件。请等到收到 `init` 后才启动辅助进程，此时后端已进入宿主管理的 Windows Job。控制消息只走标准输入和输出，不需要监听网络端口。

每条消息是单行 UTF-8 JSON，换行后刷新；标准输出只能写协议消息。收到 `exit` 或标准输入关闭时，后端须释放流、设备和窗口并退出。宿主结束时会清理其管理的子进程。

## 最小握手

宿主发出的首条请求示例：

```json
{"id":0,"name":"init","args":{}}
```

后端可回送结果，然后独立推送完整状态。后续请求也使用同一结构，请原样返回请求的 `id` 和 `name`。只有后端能接受命令时，才报告 `ready: true`。

```json
{"type":"result","id":0,"name":"init","value":{}}
{"type":"state","state":{"ready":true,"settings":{},"status":{"phase":"idle"}}}
```

例如，对未实现的操作应返回明确错误；不要回报成功或伪造帧统计：

```json
{"type":"error","id":3,"name":"devices","message":"本后端不支持枚举采集设备"}
```

`state` 是完整快照（宿主会替换上次状态）。`fatal` 加 `message` 表示不可继续的错误。可按能力支持 `discover`、`pair`、`connect`、`remote`、`capture`、`devices`、`settings`、`stop` 等请求。请求参数及界面的消费位置以 `src/panels.rs` 与 `src/main.rs` 为准。

## 视频、音量与画质反馈

- 提供嵌入式视频时，**由 `relay-backend.exe` 进程自身**创建可见的顶层 Win32 窗口（无所有者，类名 `RelayPlaybackWindow`），并从该进程输出音频。宿主以自己实际启动的进程 PID 查找此窗口和音频会话，不接受消息指定其他进程。
- 设置补丁如 `{"id":2,"name":"settings","args":{"bitrateKbps":75000}}` 表示请求 **75 Mbps**。后端应在确认后回送完整设置；如果参数只能在下次连接生效，应报告待重连设置。
- `status.phase: "streaming"` 配合 `status.stats` 报告实际帧。`width`、`height` 是处理前的输入尺寸；采集设备与输出尺寸有独立字段。`activeUpscaler`、`neuralRendering` 以及 `status.renderFeedback` 用于区分已选算法、实际算法和回退原因；没有测量时不要用目标值填充实测字段。

## 本地数据

仅使用宿主分配给当前实例的数据目录。配对或登录的输入不应出现在日志和状态快照里；只返回界面需要的字段。宿主、源码仓库与发布包均不需要预置真实账号、主机标识、配对码或授权文件。开发接入时请指向单独的 `RELAY_PLAYER_ROOT` 并使用虚构数据。

0.1.13 在 Relay 协议下只加载 RelayView 视频根项，不加载原生 Main/StreamView 的设置、菜单、快捷键、加载提示或状态窗口。原生主机发现始终禁用，搜索和唤醒由宿主执行。0.1.14 取消会话前的 RELAY_RENDER_SETTINGS 初始化；完整画质参数在引擎初始化后仅经私有 stdin 应用，实时修改复用此通道。原生帧生成默认关闭，去重不能提高用户选择的倍率；刷新率或算法上限可以降低输出。主机 PIN 请求与错误通过私有通道转交播放器。没有修改 Windows 防火墙规则或通知设置；首次授权或系统策略阻断仍由 Windows 控制。

0.1.14 在 Windows 上先创建隐藏的视频 HWND，通过 RelayPlayer.VideoReady.V1 属性表明交接就绪。宿主验证已启动进程的 PID、Qt 窗口类、无外部所有者及交接属性后接管；嵌入前不显示顶层窗口。原先隐藏的窗口在释放时保持隐藏，不应用会将其显示的 WINDOWPLACEMENT。Relay 模式不合成空 Qt Quick 叠层。sessionEnded 仅包含固定枚举原因；最近主机仅在收到视频后写入加密授权存储，底栏重连使用此记录。

0.1.16 的公开连接流程由 src/wake.rs 在独立可取消任务中先检查 DDP 状态，待机时按已有配对凭证发送 WAKEUP，等到匹配主机返回 ready 且 TCP 9295 可连接后才调用 prepare_stream/launch_stream。主机启动等待最多 60 秒，唤醒最多重试五次。停止会清除目标与任务，取消之后的 Ready 不再启动引擎；UI 以原 waking 阶段显示过程。地址更新只有收到实际视频后才写入加密库。

0.1.16 的用户停止、正常退出及独立播放窗口关闭，通过私有 stdin 发送 {"type":"stop","standby":true}，由已有授权会话请求主机待机，留出 250 ms 发送窗口后停止。设置自动重连发送 standby:false，保持主机开机。宿主退出仍在销毁嵌入表面之前结束引擎，清理有界且无原生确认框。连接前取消不会新建会话请求待机，断网或异常强制结束进程不保证主机待机。
