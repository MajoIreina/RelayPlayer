# Relay render adapter

Base: `windystrife/chiaki-ng-Ultimate` commit `3c64539c7496bbd212122d2e0d7aff319bafb90e`.
Apply `relay-render.patch` at that checkout, then copy the accompanying `gui/` files there. Initialize the upstream submodules, and apply upstream's Windows `<intrin.h>` fix in gf-complete (included in the corresponding source archive).

The adapter uses inherited stdin for bounded JSON settings and stdout for bounded status events. It starts only direct streams or capture. Relay owns pairing, UI and a bound per-profile registry namespace. No network control server is added. UI text and the schema remain in `src/playback.rs`.

Build dependencies used: Qt 6.9.3 MSVC x64, LLVM/clang-cl 23.1.6, CMake/Ninja, NVIDIA DLSS SDK headers/import library, FFmpeg n7.1 shared GPL libraries, libplacebo API 360 (7.360.1 headers), and vcpkg commit `9eec002df1cd109f8f104cd966a763daf9751489` (SDL2, protobuf, OpenSSL, json-c, libevent, miniupnpc, opus, lcms, speexdsp, Vulkan).

Configure Release with `CHIAKI_ENABLE_NGX=ON`, `CHIAKI_ENABLE_FFX_SOURCE=OFF`, tests/CLI/setsu/Steamdeck/Steam shortcuts off. Point `CHIAKI_NGX_SDK_DIR`, `CMAKE_PREFIX_PATH` and `CMAKE_TOOLCHAIN_FILE` to those dependencies. Build targets `chiaki` and `chiaki-fgdx12test`. The GPU test accepts `--relay-render-test`; copy genuine ArtCNN assets to `relay-artcnn/` and the upstream FSR shader to `fsr.glsl` for that test only.

The backend source keeps its upstream license and attribution. NVIDIA runtimes/models have separate licenses and are acquired from pinned sources; they are not described as open source. `tools/relay-render-manifest.json` binds the final native files; `tools/ensure-relay-render.ps1` verifies the overlay and downloads NVIDIA VFX from NVIDIA. The program downloads and stores dependencies alongside its installation, not in a new system installation.

The adapter also accepts `{"type":"stop"}` on inherited stdin: it stops the session without a sleep prompt or standby request. Window close follows the same policy only while Relay's protocol is enabled. Status events carry the renderer's GPU/driver identity, actual picture source, measured input bitrate in Kbps, presented output fps, named frame generation and NR evidence. NR is confirmed by processed frames; an untested GPU is not advertised as supported. The headless GPU helper accepts `--relay-telemetry-test` to verify the report builder against a real Vulkan device and synthetic NR frame.

For 0.1.13 also copy the public repository asset assets/relay.ico to gui/relay.ico before building. The upstream copyright remains in the resource and bundled notices. Relay mode loads only RelayView.qml, creates no native settings or stats windows, disables native shortcuts and discovery, and accepts validated settings over inherited stdin after initialization (0.1.14 removes the earlier duplicate environment-based apply). PIN requests use pinRequired events and the private pin command. --relay-policy-test checks multiplier bounds across dedup/refresh/backend limits. The isolated relay-self-test command verifies the real QML root, absence of native stats, disabled shortcuts/discovery and initial settings without showing a window or contacting a console.

For 0.1.14 the Windows video HWND starts hidden and carries the RelayPlayer.VideoReady.V1 property with its PID. The verified Rust host adopts it before showing; do not filter these marked owned surfaces out merely because they are hidden. Restoring a hidden window must not apply a normal-show WINDOWPLACEMENT. Relay never composites its empty Quick scene over video. The relay-render-test command generates synthetic RGB frames without a console/device; RELAY_RENDER_VERIFY_PRESENT=1 enables a diagnostic GPU readback of nonblack pixel count/range only, with no image export. These are opt-in diagnostics and are absent from normal playback. sessionEnded reports the fixed library reason, excluding the private console response.
